# SmashOne Brand Assets — единый банк изображений

Публичный репозиторий визуальных материалов **SmashOne**. С 28.08.2026 это **единый банк
изображений компании** (решение Валерия): сюда кладут и отсюда берут — Мира (дизайн и маркетинг),
Дон (видео), Джей (публикации в соцсетях).

> **Владелец бренда:** SMASHONE CORPORATION (Florida C-Corp, P26000023598) · домен `smashone.us`
> **Публичность репозитория** нужна ради raw-URL: Claude Design подтягивает картинки по ссылке,
> и без публичного доступа промпты приходят с пустыми слотами.

**Raw-база:**

```
https://raw.githubusercontent.com/smashone-corp/smashone-brand-assets/main/<путь>
```

Пример: `https://raw.githubusercontent.com/smashone-corp/smashone-brand-assets/main/logos/smashone-logo/smashone-logo.svg`

## 🔴 Пять правил банка

1. **Одна вещь — одно место.** Нужен факт (лицо героя, логотип, иконка) — у него ровно один
   канонический путь. Копия в двух местах — это будущее противоречие, а не подстраховка.
2. **Ссылка живёт дольше файла.** На пути этого репозитория бьют сотни raw-ссылок из промптов,
   нарядов и экспортов. Удалённый или переименованный файл **не ломает сайт** (витрина работает
   с локальными копиями), но молча ломает промпты и дизайн-систему: auto-fetch получает 404 и
   рисует пустой слот.
   🔴 **Уточнено 02.09.2026 — прежняя редакция противоречила правилу 1.** Здесь стояло «файл не
   переименовывают и не двигают: делают КОПИЮ, а оригинал остаётся» — то есть правило 2 требовало
   ровно того, что правило 1 запрещает («копия в двух местах — будущее противоречие»). Оба
   прочитать одновременно нельзя, и в тот день это стоило третьего дома для одного лица.
   **Действующая редакция:** переносить и переименовывать МОЖНО — копий не плодим, — но **только
   после проверки потребителей** (блок ниже) и одной волной со всеми, кто на файл ссылается.
   Решения того дня по этому правилу: переезд героев в один дом, `wes-*` → `sage-*`.
3. **Сначала снимают ссылки, потом двигают файлы.** Обратный порядок уже стоил 207 битых ссылок
   на один логотип.
4. **Чужих и стоковых лиц не бывает.** Лица владельцев бизнеса — только из `heroes/`.
5. **Снятое УДАЛЯЕТСЯ, папок `_archive/` не заводим.** Архив банка — это его **git-история**:
   удалённый файл достаётся из неё в любой момент, а копия «на всякий случай» рядом с живым
   деревом превращается в третий дом для того же лица (проверено 02.09: два дома героев дали
   дубликаты в тот же день, когда завелись). Действует указание владельца 27.08.2026.
   🔴 Именно поэтому удаление здесь **необратимо для ССЫЛОК, а не для файлов**: сам файл
   в истории останется, но каждый, кто читал его по raw-CDN, получит 404 — и потому перед
   удалением обязательна проверка ниже, а не после него.

### 🔴 ПРОВЕРКА ПЕРЕД ЛЮБЫМ ПЕРЕИМЕНОВАНИЕМ И УДАЛЕНИЕМ (вписано 02.09.2026 — Мира, по своей вине)

```bash
# 1. собрать все CDN-адреса потребителей
grep -rho 'smashone-brand-assets/main/[A-Za-z0-9._/-]*' <дизайн-система> <сайт> <наряды Джея>   | sed 's|.*main/||' | sort -u > /tmp/refs.txt
# 2. спросить у живого банка КАЖДЫЙ, а не выборочно
while read -r r; do
  c=$(curl -s -o /dev/null -w "%{http_code}" "https://raw.githubusercontent.com/smashone-corp/smashone-brand-assets/main/$r")
  [ "$c" != "200" ] && echo "🔴 $c $r"
done < /tmp/refs.txt
```

**Цена, из-за которой проверка стоит выше удобства.** 02.09.2026 переименование и удаление
в этом банке за одну смену увели **24 ссылки дизайн-системы в 404** (12 файлов), а снятая
папка `heroes/marcus-bell/` была определена в фикстурах ТРИЖДЫ и питала шесть превью.
Ни сборка, ни сайт об этом не сказали — узналось только сплошной проверкой адресов.

**Почему это отдельный блок, а не шестое правило.** Правила 2 и 3 выше запрещают ровно то, что я
сделала 02.09: переименовала `wes-*` → `sage-*` и удалила папку `heroes/marcus-bell/`. **Правило
существовало — не хватало проверки, привязанной к моменту действия.** Правило, живущее в тексте,
исполняется по памяти; исполняется то, что стоит рядом с рукой.

🔴 **«На сайте всё цело» проверкой НЕ является:** витрина держит локальные копии в
`web/public/assets/brand/**` и не заметит ничего. Банк по CDN читает **дизайн-система**.

### 🔴 ДВА СПОСОБА, КОТОРЫМИ ЭТА ПРОВЕРКА ВРЁТ (замерено 02.09.2026 на волне из 111 файлов)

**(1) Прибор слеп, если ищет ТОЛЬКО полное имя файла.** Часть путей собирается из данных:
в исходниках стоит `roster/${portrait}.webp`, то есть основа имени без расширения. Поиск по
`sloane.webp` не находит Слоан, хотя её показывает каждая вторая страница. На слепом приборе
«ни одной ссылки не найдено» означает **«я не измеряла»**, а не «файл мёртв» — и удаление по
такому ответу сносит живое.
🔴 **Поэтому прибор проверяется контролем В ОБЕ СТОРОНЫ ДО того, как ему поверят:** взять
два-три файла, которые сайт ТОЧНО показывает (обязаны найтись), и одно выдуманное имя
(обязано промолчать). Не прошёл контроль — чинить прибор, а не удалять файлы.

**(2) Архив, который называет имя, — НЕ потребитель.** Первый широкий проход дал «111 попаданий
из 111» и был бесполезен: он считал читателями журналы прогонов QA, завершённые наряды в `done/`,
генерируемое зеркало `ASSET-INDEX` и сам список кандидатов, написанный часом раньше.
- **потребитель** = то, что отдаст битый результат, если файл исчезнет: исходники сайта и
  кабинетов, фикстуры дизайн-системы, каталоги демо-бизнесов, манифесты, живая база знаний;
- **запись о прошлом** = журнал, архив, генерируемое зеркало, таблица уже ИСПРАВЛЕННЫХ ошибок.

Иначе любой архив держал бы файл вечно — а архив на то и архив, чтобы помнить и то, чего больше нет.

**Последняя проверка — на поверхности показа, а не в исходниках:** собрать сайт и грепнуть
удаляемые имена по `dist/`. Греп по `src/` пропускает то, что подставляется при сборке.

## Кто что кладёт

### 🎨 Мира — канон

Логотипы, фавикон, иконки, фотобиблиотека, оформление каналов, портреты ролей,
карточки выпусков, **канон героев** (`heroes/<slug>/README.md`, `anchor/`, `scenes/SCENES.md`).

Правит `heroes/` только вместе с реестром `design/knowledge/characters-registry.md` — иначе
банк и реестр разъедутся.

### 🎬 Дон — видео

Кладёт **только** в:

```
heroes/<slug>/avatars/        — аватары героя (photo/video), по файлу на версию
heroes/<slug>/video-masters/  — видео-мастера и боевые рендеры
social/video/<YYYY-MM>/       — готовые видеовыпуски корпканалов
```

Имя файла: `<slug>-<что>-<версия>.<ext>` (например `marcus-bell-green-waist-v2.png`).
🔴 **avatarId живёт в реестре персонажей, не здесь.** Пересоздал аватар — новый id идёт
в `characters-registry.md` и в Notion «Видеостудия SmashOne», старый помечается мёртвым.

### 🗽 Джей — поле

Берёт готовые карточки из `social/posts/<YYYY-MM>/` и публикует руками в Facebook / Instagram /
X / LinkedIn. Кладёт обратно — в ту же папку месяца, если снял скрин или собрал материал с площадки.
Ничего не переименовывает и не двигает.

## Правила именования

| Что | Форма | Пример |
|---|---|---|
| Папки и файлы | `kebab-case`, латиница, без пробелов | `marcus-bell-master.png` |
| Герой | slug героя = имя папки в `heroes/` | `marcus-bell`, `yamila-ortiz` |
| Карточка выпуска | `<код>-<YYYY-MM-DD>-{45,sq}.png` | `b6-2026-08-30-45.png` |
| Видеовыпуск | `<код>-<YYYY-MM-DD>-{169,916}.mp4` | `f3-2026-08-28-169.mp4` |
| Произв. сцена | `scene_<сюжет>_{45,sq,169,916}.webp` | `scene_f3_marcus_stove_phone_45.webp` |
| Иконка соцсети | `<сеть>-{color,mono,tile}.svg` | `telegram-tile.svg` |
| Версия | суффикс `-v2`, `-v3`; **старую версию не перезаписывать** | `avatar-1024-v2.png` |
| Размер растра | суффикс пикселями | `icon-512.png`, `favicon-32x32.png` |

Фото — `.webp` (компактно), знаки и иконки — `.svg`, мастера аватаров и растровые аватары — `.png`.

## Бренд-константы

- **Логотип-канон:** `logos/smashone-logo/smashone-logo.svg` — золотой знак, theme-agnostic.
  ⚰️ `smashone-logo-potrace.svg` **мёртв** — ссылки на него дают 404.
- **Фавикон (LOCKED 25.08.2026):** золотой знак **без чёрной плашки** — `logos/favicon/`.
  Чёрный квадрат под знаком = дефект.
- **Золото:** `#b08930` — hex не меняется; текст на золоте всегда тёмный (`#1a1406`), не белый.
- **Шрифты:** Onest (display) · Inter (body) · IBM Plex Mono (табличные числа).
- **Тема:** light-first. Тёмный режим — только пульт сервис-контура (админ-консоль).

Полный канон токенов — `design/knowledge/canonical-css-tokens.md` и библиотека DS v2
(`design/ds-v2/`), не этот репозиторий.
